# desyp-event

[대규모시스템프로젝트] 선착순 5만원 이벤트!

De_sy_P 사전등록 페이지. Vite + React + TypeScript로 만든 정적 SPA. 네이버 로그인으로만 사전등록을 받고, 로그인 처리와 저장은 별도 백엔드가 맡는다. 백엔드 주소가 없으면 목업 API로 동작한다.

## 실행

```bash
npm install
cp .env.example .env   # 값 채우기
npm run dev             # http://localhost:5173
npm run build            # dist/ 에 정적 빌드
npm run preview          # 빌드 결과 로컬 확인
```

## 환경 변수 (`.env`)

| 변수                  | 필수 | 설명                                                         |
| --------------------- | ---- | -------------------------------------------------------------- |
| `VITE_REGISTRATION_END_AT`   | O    | 사전등록 마감 시각(이벤트 하루 전). ISO 8601, KST 오프셋 포함 (`+09:00`)         |
| `VITE_RETENTION_DAYS` | O    | 개인정보(네이버 id·이메일, 응모 Instagram 아이디) 보유 기간(일). 이벤트 종료 후 이 기간 안에 파기한다. 비어 있으면 `npm run build`가 실패한다 |
| `VITE_KAKAO_CHANNEL_URL` | O | 사전등록 완료 화면의 "카카오톡으로 이벤트 알림 받기" 버튼이 새 창으로 여는 카카오톡 채널 주소. 비어 있으면 `npm run dev`·`npm run build`가 실패한다 |
| `VITE_API_BASE_URL`   | X    | 비워두면 목업 API 사용. 채우면 사전등록과 메인 이벤트 모두 이 주소로 실제 요청 |

메인 이벤트용 새 환경 변수는 없다. 이벤트 시각(2026-10-31 14:00~14:10 KST)은 `src/api/mainEvent.ts`에 고정값으로 두고, 서버 응답의 `startAt`·`endAt`이 오면 그 값을 쓴다. 보관 기간 안내는 `VITE_RETENTION_DAYS`를 같이 쓴다.

## 사전등록 흐름

1. **로그인 전:** "네이버로 로그인" 버튼만 보인다.
2. **로그인 후:** 가린 이메일, 추천 코드 입력칸(선택), 동의 체크박스 3개(만 14세 이상·개인정보 수집·오픈 알림 수신, 모두 필수), "사전등록하기" 버튼이 보인다.
3. **등록 완료:** "사전등록 완료!", 이메일·카카오톡 채널 안내 문구, "카카오톡으로 이벤트 알림 받기" 버튼, 추천 코드가 보인다. 버튼을 누르면 클릭 기록 API를 호출하고, 응답과 관계없이 카카오톡 채널을 새 창으로 연다. 목업은 기록 API를 호출하지 않는다. 마감 시각이 지나면 모든 단계 대신 마감 안내가 보인다.

`VITE_API_BASE_URL`이 비어 있으면 목업으로 동작한다. 로그인 버튼을 누르면 바로 로그인된 상태가 되고, 새로고침하면 초기화된다. 추천 코드에 `ZZZZZZZZ`를 넣으면 찾을 수 없음 응답을 볼 수 있다.

**수집 정보와 용도:** 네이버 계정 식별자와 이메일만 받는다. 휴대전화번호는 수집하지 않는다. 중복 등록은 네이버 계정과 이메일 기준으로 막는다. 이메일은 1차 공식 알림 수단으로, 이벤트 시작 1시간 전 안내와 당첨 연락에 쓴다. 카카오톡 채널은 선택적 보조 알림 수단이다. 버튼 클릭만 기록하며 실제 채널 추가 여부나 카카오 계정 정보는 알 수 없다.

## 백엔드 API

프론트는 아래 다섯 API를 호출한다. 모두 `VITE_API_BASE_URL` 기준이며, 세션은 쿠키로 유지한다. 백엔드는 `https://api.desyp.site`이고, 같은 사이트의 하위 도메인이라 쿠키는 `SameSite=Lax; Secure; HttpOnly`로 동작한다. CORS는 `https://www.desyp.site`만 허용하므로, Vercel 미리보기 주소(`*.vercel.app`)에서는 목업으로 확인한다.

로컬에서 실제 백엔드에 붙일 때는 `.env`에 `VITE_API_BASE_URL=http://localhost:8080`을 넣는다. 로그인은 네이버 개발자센터 멤버관리에 등록된 테스터 계정만 된다.

| 요청 | 설명 |
| ---- | ---- |
| `GET /auth/naver/login?return_to=<URL>` | 브라우저가 이 주소로 이동한다. 백엔드가 `state`를 만들어 네이버 인증 페이지로 보내고, 콜백에서 토큰 교환과 프로필 조회(`/v1/nid/me`의 `id`, `email`) 후 세션을 만든다. 끝나면 `return_to`로 돌려보낸다 |
| `GET /api/me` | 로그인 상태면 `200 { "emailMasked": "des***@naver.com", "registered": false }`, 아니면 `401` |
| `POST /api/pre-registrations` | 본문 `{ "ageConfirmed": true, "agreePrivacy": true, "agreeMarketing": true, "referralCode": "..." }`. 추천 코드는 선택이며 이메일 같은 개인정보를 추천 식별자로 보내지 않는다. 성공 응답은 본인의 `referralCode`를 반환한다 |
| `GET /api/referrals/me` | 사전등록한 로그인 사용자의 추천 코드, 실제 추천 수, 코드 사용 보너스, 총점을 반환한다 |
| `POST /api/conversions/kakao-channel-click` | 본문 `{ "source": "PRE_REGISTRATION_COMPLETE" }`. 사전등록 완료자의 카카오톡 채널 버튼 클릭을 기록하고 `204`를 반환한다. 같은 사용자·source는 한 번만 저장된다. 실패해도 프론트는 무시하고 채널을 연다 |

**로그인 실패 시** `return_to`에 `?login=error&reason=<이유>`를 붙여 돌려보낸다. 프론트가 아는 이유는 `no_email`(제공 거부)과 `cancelled`(사용자 취소)이다. `failed`(그 외 실패)와 모르는 이유는 일반 실패 안내를 띄운다.

**등록 요청 응답 코드**

| 코드 | 의미 |
| ---- | ---- |
| `2xx` | 등록 완료 |
| `400` | 동의 누락·형식 오류 |
| `401` | 세션 만료. 프론트가 로그인 전 단계로 되돌린다 |
| `404` | 유효하지 않은 추천 코드 |
| `409` | 이미 등록한 네이버 계정 또는 이메일 |
| `410` | 마감 이후 요청. 마감 시각은 서버에서도 확인해야 한다 |
| `415` | JSON이 아닌 요청 |
| `429` | 요청이 너무 잦음. 배포할 때 API Gateway에서 설정 예정 |

응답 본문에 `{ "message": "..." }`가 있으면 프론트는 기본 문구 대신 그 문구를 그대로 모달에 띄운다. 400·415처럼 표에 따로 처리가 없는 코드는 일반 오류로 다루되, 역시 `message`를 띄운다.

## 메인 이벤트 (응모)

사전등록이 끝나면 히어로의 사전등록 카드 자리가 응모 카드로 바뀐다.

### 화면 상태

단계는 클라이언트 시계가 아니라 `GET /api/event/status`의 `serverTime`과의 차이를 보정한 시계로 계산한다. 상태는 폴링하지 않고, 페이지 진입과 단계가 바뀌는 순간(그리고 응모가 `410`을 받았을 때)에만 0~3초 무작위 지연 후 다시 불러온다.

| 단계 | 기간 (KST) | 화면 |
| ---- | ---- | ---- |
| 사전등록 | ~ 10/30 23:59 (`VITE_REGISTRATION_END_AT`) | 기존 사전등록 카드 그대로 |
| 대기 | 마감 ~ 10/31 14:00 | 시작 카운트다운, 참여 방법·당첨 방식 안내. Instagram 아이디와 만 14세 확인은 미리 할 수 있고 응모 버튼은 잠겨 있다 |
| 응모 중 | 14:00 ~ 14:10 | Instagram 아이디, [필수] 만 14세 확인, "응모하기", 종료 카운트다운, 이번 세션 응모 횟수와 최근 접수 번호 5개 |
| 종료 | 14:10 ~ | 마감 안내, 발표된 랜덤 번호(없으면 "곧 발표"), 이번 세션 내 접수 번호 전체, Instagram DM 안내 |

### 응모 팝업

1. "응모하기"를 누르면 바로 버튼을 잠근다. 응답을 기다리는 동안 버튼에 "접수 중..."이 보인다.
2. 응답이 오면 "접수 번호 #N" 팝업이 버튼을 덮는다. 떠 있는 동안 아래 버튼은 눌리지 않는다.
3. 응답을 받은 때부터 1초 뒤 팝업이 내려가고 버튼이 다시 열린다. 이 1초가 연속 응모 간격이며 `MainEventCard.tsx`의 `POPUP_MS`로 바꾼다.
4. 실패하면 팝업 대신 기존 결과 모달로 오류 문구를 띄우고 버튼을 다시 연다.

애니메이션은 `transform`·`opacity`만 쓰고, 동작 줄이기 설정에서는 슬라이드 없이 나타났다 사라진다. 팝업에는 접수 번호만 보이고 당첨 여부는 보이지 않는다.

**입력값:** Instagram 아이디는 앞의 `@`를 지우고 소문자로 바꾼 뒤 영문·숫자·`.`·`_` 1~30자만 받는다. 아이디와 받은 접수 번호는 `sessionStorage`에 둬서 이번 세션 동안 다시 입력하지 않아도 된다. 휴대전화번호 등 다른 개인정보는 받지 않는다.

**트래픽 대응:** 응모마다 `crypto.randomUUID()`로 `requestId`를 새로 만든다. `429`·`503`·네트워크 오류는 같은 `requestId`로 지수 백오프와 jitter(0.4~0.8초, 0.8~1.2초, 1.6~2.0초)를 두고 최대 3번 더 보낸다. 14:00 정각 몰림을 줄이려고 응모 버튼은 0~1초 무작위로 늦게 열린다.

### 메인 이벤트 API

로그인이 필요 없어 쿠키를 보내지 않는다. 사전등록 여부와도 무관하다.

| 요청 | 응답 |
| ---- | ---- |
| `GET /api/event/status` | `200 { "phase": "BEFORE"\|"OPEN"\|"CLOSED", "startAt": ISO, "endAt": ISO, "serverTime": ISO, "randomNumber": number\|null }`. `randomNumber`는 이벤트 종료 직후 발표 전까지 `null` |
| `POST /api/event/entries` | 본문 `{ "requestId": "uuid", "instagramId": "string", "ageConfirmed": true }`. 새 응모면 `201 { "receiptNumber": number }`, 같은 `requestId`를 다시 받으면 처음 발급한 번호로 `200 { "receiptNumber": number }` |

| 코드 | 의미 |
| ---- | ---- |
| `400` | 형식 오류 (아이디 형식, `ageConfirmed` 누락 등) |
| `410` | 응모 시간이 아님. 시간은 서버에서 판단한다 |
| `429` | 요청이 너무 잦음. 프론트가 자동 재시도한다 |
| `503` | 혼잡. 프론트가 자동 재시도한다 |

오류 본문에 `{ "message": "..." }`가 있으면 그 문구를 그대로 모달에 띄운다.

**당첨:** 선착순은 접수 번호 1번, 랜덤은 이벤트 전에 정해 둔 번호(응모 수가 그보다 적으면 마지막 접수 번호), 추천왕은 사전등록 추천 점수 1위다. 당일 당첨자는 입력한 Instagram 아이디로, 추천왕은 네이버 이메일로 운영자가 연락한다.

### 목업으로 확인하기

`VITE_API_BASE_URL`이 비어 있을 때만 동작한다. 접수 번호는 메모리에서 1씩 오르고, 응답은 200~600ms 늦게 온다. 새로고침하면 초기화된다(브라우저에 남은 내 접수 번호 목록은 탭을 닫아야 지워진다).

- `?mockPhase=registration|waiting|open|closed`: 서버 시계를 그 단계로 옮긴다. `registration`·`waiting`은 다음 단계 30초 전, `open`·`closed`는 시작·종료 1초 뒤다. 실제 모드에서는 무시한다
- Instagram 아이디 `error` → `503`(재시도 3번 뒤 오류 모달), `slow` → 3초 지연, `badrequest` → `400`, `closed` → `410`
- 종료 단계의 랜덤 번호는 `7`(응모가 7개보다 적으면 마지막 번호)

## 배포 (Vercel)

Vite 프로젝트라 프레임워크 프리셋이 자동 인식된다. 빌드 커맨드 `npm run build`, 출력 디렉터리 `dist`.

```bash
npx vercel        # 최초 배포 (로그인 필요)
npx vercel --prod # 프로덕션 배포
```

Vercel 프로젝트 설정의 Environment Variables에 `VITE_REGISTRATION_END_AT`, `VITE_RETENTION_DAYS`, `VITE_KAKAO_CHANNEL_URL`(필수), `VITE_API_BASE_URL`(선택)을 등록해야 빌드가 성공한다.
